# Post-hoc conversion to a differential-head Transformer: faithful low-rank split + continue pretraining

Branch `agent/faithful-lowrank-split-cpt-2026-08-17`. Every number is generated by `scripts/make_final_report.py` from the JSON artifacts named inline; none is transcribed by hand. The 2026-08-14 LocalRead method and all of its artifacts are preserved unchanged as comparison arm E.

## Headline

1. The faithful token-local low-rank split is **function-preserving to the bit** on the real Qwen3-4B (fp32 and bf16, eager and sdpa), adds **0 bytes** of per-sequence inference state where the LocalRead method it replaces adds **21,934,080**, and trains exactly 14,137,344 parameters.

2. It **beats the LocalRead split it replaces**: +0.00443 nats in LocalRead's favour is actually -0.00443 for the low-rank split, 95% CI [+0.00429, +0.00456], p=0.0000, same sign in every seed. But it **ties the parameter-matched additive control**: -0.00003 nats, CI [-0.00026, +0.00017], p=0.776. That is a *tight* null, not an underpowered one: the two are equal to within ~0.0003 nats. Spending the same parameters additively, with no differential attention branch at all, is just as good. (Paired intervals: continuation arms with the same seed load the same T0 and the same token stream, so the design is matched.)

3. The **native DiffV2 reference advantage fails its pre-registered gate**: -0.00708 nats, CI [-0.01461, +0.00010], p=0.054, against a measured seed-noise floor of 0.01230. **Recovery ratio = N/A** (denominator 0.00708 does not exceed the measured seed-noise floor 0.01230; ratio would be division on noise).

4. That advantage **decays with training** (256-window in-training eval at matched steps): -0.0359 nats at 210M tokens, -0.0070 at 420M, -0.0048 at 800M. It is a convergence-speed effect, not an asymptotic quality difference. The 2026-08-14 figure (~0.005 nats at 480M tokens on C4 @ seq 1024) lies on the same curve, so the two studies agree rather than conflict.

5. **No adapter arm approaches simply continuing to train the dense model.** Every one loses to `vanilla_continue` by 0.070-0.080 nats at p=0.0000, at the same token budget.

## Does the *faithful* placement matter? (pre-norm vs post-norm delta)

The central design claim is that adding the delta BEFORE `q_norm` makes the module a reparameterization of one query matrix, `q_norm((Wq+BA)h)`, which is the native DiffV2 query path, whereas adding it after `q_norm` (what LocalRead does) is an additive patch on an already-normalized vector. This ablation runs the identical module with the delta moved after the norm, same rank, same T0, same stream, 3 seeds.

| arm | mean val NLL |
|---|---|
| `lowrank` | **3.52866** |
| `lowrank_postnorm` | **3.52889** |
| `localreader` | **3.53309** |

Paired: **-0.00023** nats, CI [-0.00034, -0.00011], p=0.0000, per-seed [-0.000323, -9.6e-05, -0.000273], same sign True.

**Read this carefully.** Pre-norm is *statistically* better -- the paired interval excludes zero and the sign is the same in every seed -- but the magnitude is 0.00023 nats, which is 5% of the gap this method opens over LocalRead (0.00443) and 1/53 of the seed-noise floor. So the faithfulness argument that motivated this design is vindicated in direction and almost irrelevant in size: essentially all of the improvement over LocalRead comes from the negative query being **token-local** (no window reader at all), not from where the delta sits relative to `q_norm`.

## What would change the conclusion

* A scale where 800M tokens is *early* training. The native advantage here is real early and decays; a larger model may not reach the regime where it vanishes within a realistic budget.
* More seeds. 3 seeds fix the noise floor at 0.0123; resolving a 0.007 effect against it needs roughly an order of magnitude more runs.
* A task with retrieval-shaped supervision rather than plain LM loss. The position analysis suggests the differential branch is not doing long-range work under next-token prediction.
